---
title: "Get started with ngitflow"
description: "Install ngitflow and go from a bare Git repository to a tagged release: set up Git Flow branches, work a feature, and ship a release in minutes."
---

This guide takes you from a bare Git repository to a tagged release using ngitflow. You'll install the tool, set up the Git Flow branch structure, work through a feature branch, and finish a release — covering the core workflow you'll repeat every time.

<Steps>
  <Step title="Install git-flow AVH Edition">
    ngitflow calls `git flow` commands directly, so git-flow (AVH Edition) must be installed on your machine before you begin.

    Follow the [installation instructions for your operating system](https://github.com/petervanderdoes/gitflow-avh/wiki/Installation) on the official git-flow AVH wiki.

    Verify the installation by running:

    ```bash
    git flow version
    ```
  </Step>

  <Step title="Install ngitflow">
    Install ngitflow as a dev dependency in your project, or globally if you prefer a system-wide command.

    <CodeGroup>

    ```bash npm (dev dependency)
    npm install --save-dev ngitflow
    ```

    ```bash npm (global)
    npm install -g ngitflow
    ```

    </CodeGroup>

    When installed locally, run commands with `npx ngitflow`. When installed globally, use `ngitflow` directly.
  </Step>

  <Step title="Initialize the repository">
    Run `ngitflow init` inside a Git repository to set up the Git Flow branch structure.

    ```bash
    npx ngitflow init
    ```

    This creates the `master` and `develop` branches and configures git-flow for the repository. All ongoing development happens on `develop`, which you should set as the default branch in your Git hosting provider.

    <Note>
      After `init`, your `package.json` version on `develop` should follow the snapshot convention — for example, `1.0.0-snapshot.0`. This signals that the branch contains unreleased work in progress.
    </Note>
  </Step>

  <Step title="Start a feature">
    When you begin work on a new feature, create a feature branch with:

    ```bash
    npx ngitflow feature start my-feature
    ```

    This creates a `feature/my-feature` branch from `develop` and bumps the version in `package.json` to reflect the feature name — for example, `1.0.0-snapshot.0` becomes `1.0.0-my-feature.0`. If you omit the name, ngitflow generates a random identifier.

    Make your changes on this branch, commit them as normal.
  </Step>

  <Step title="Finish the feature">
    When your feature is ready to merge back:

    ```bash
    npx ngitflow feature finish
    ```

    ngitflow merges the feature branch into `develop`, deletes the feature branch, and resets the version back to the snapshot (e.g. `1.0.0-snapshot.0`).
  </Step>

  <Step title="Start a release">
    When `develop` is ready to ship, create a release branch:

    ```bash
    npx ngitflow release start
    ```

    By default this bumps the `patch` segment and removes the snapshot prerelease, turning `1.0.0-snapshot.0` into `1.0.1`. You can target a different level or a specific version:

    ```bash
    npx ngitflow release start minor
    npx ngitflow release start major
    npx ngitflow release start 2.0.0
    ```
  </Step>

  <Step title="Finish the release">
    Once the release branch is ready:

    ```bash
    npx ngitflow release finish
    ```

    ngitflow:

    1. Creates a Git tag for the release version (e.g. `1.0.1`)
    2. Merges the release branch into `master`
    3. Merges the release branch back into `develop`
    4. Bumps `develop` to the next patch snapshot (e.g. `1.0.2-snapshot.0`)
    5. Deletes the release branch

    `master` retains the release version; `develop` moves forward to the next snapshot.
  </Step>
</Steps>

## Recommended npm scripts

Add these scripts to your `package.json` to make the release workflow available as short npm commands:

```json
{
  "scripts": {
    "release:start": "ngitflow release start",
    "release:finish": "ngitflow release finish",
    "release": "ngitflow release start && ngitflow release finish"
  }
}
```

With these in place, you can run `npm run release` to start and finish a release in one step.
